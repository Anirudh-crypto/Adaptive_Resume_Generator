% Static document used only to pre-warm Tectonic's package bundle cache during the Docker build.
%
% Companion to prewarm.tex. There are two resume layouts with genuinely different preambles, so
% there are two prewarm files -- one mirroring each. Compiling a single combined document instead
% would risk the two package sets fighting each other (fullpage and geometry both want the
% margins), and would break the one-to-one "keep this in sync with that template" rule.
%
% This one mirrors resume_in.tex.jinja. Keep the package list identical to it: anything loaded
% there but missing here gets downloaded on the first real compile in production, which is slow at
% best and fails outright if egress is blocked.
%
% Note what is deliberately absent, matching the template: fontawesome5 (crashes Tectonic with a
% heap corruption while loading its OTF through the XeTeX helper) and marvosym (unused). The
% glyphtounicode input is guarded the same way, since it is pdfTeX-only.
\documentclass[letterpaper,11pt]{article}

\usepackage{latexsym}
\usepackage[empty]{fullpage}

\usepackage[usenames,dvipsnames]{color}

\setlength{\columnsep}{-1pt}

\fi

\pagestyle{fancy}
\fancyhf{}
\fancyfoot{}
\renewcommand{\headrulewidth}{0pt}
\renewcommand{\footrulewidth}{0pt}

\addtolength{\oddsidemargin}{-0.6in}

\fi

\renewcommand\labelitemi{$\vcenter{\hbox{\tiny$\bullet$}}$}

% Every size/series/shape this template can reach -- see the equivalent note in prewarm.tex.
% Tectonic fetches font metrics lazily and separately from .sty files, so loading the packages is
% not enough: the tiny bullet inside resumeItem (TU/lmr at 6pt) was missing from the cache and made
% a network-less compile fail. Note this sweep is NOT interchangeable with prewarm.tex's -- that
% one loads fontenc T1 and so caches ec-lm* metrics, while this preamble has no fontenc and stays
% on XeTeX's default TU encoding, pulling the lmroman* OTFs instead.

  $\vcenter{\hbox{$\bullet$}}$ 0123456789\par}
